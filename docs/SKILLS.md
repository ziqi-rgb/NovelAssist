# 🛠 执行 Agent 能力需求文档 (Skills Specification)

本文档定义执行 Agent 完成本项目开发任务所需的全部能力和权限。

## 1. 文件系统操作能力

| 操作 | 用途 | 优先级 |
|------|------|--------|
| `read_file` | 读取指定路径的代码文件内容 | **必须** |
| `write_file` | 创建新文件或覆盖写入代码 | **必须** |
| `edit_file` | 精准修改文件中的特定行或函数（避免大文件全量重写出错） | **必须** |
| `list_dir` / `glob` | 查看目录结构，了解当前项目状态 | **必须** |
| `grep` | 在代码库中搜索特定模式，定位相关代码 | **必须** |

### 注意事项
- 修改文件前必须先 `read_file` 确认当前内容。
- 优先使用 `edit_file` 做精准修改，避免全量重写大文件。
- 新建文件前必须确认父目录已存在。

## 2. 终端/Shell 执行能力

| 操作 | 用途 | 优先级 |
|------|------|--------|
| `run_command` | 执行控制台命令 | **必须** |
| 捕获 stdout/stderr | 将命令输出写入执行报告 | **必须** |
| 超时控制 | 避免命令无限挂起 | **推荐** |

### 支持的命令类型
- **包管理:** `pip install`, `npm install`, `poetry add`
- **代码质量:** `ruff check`, `mypy`, `pytest`, `coverage`
- **Git 操作:** `git status`, `git diff`, `git add`, `git commit`, `git log`
- **项目运行:** `uvicorn`, `fastapi dev`, `python -m writer`

### 注意事项
- 执行 `git commit` 前必须确认用户（架构师）明确授权。
- 不得执行破坏性命令 (`rm -rf`, `git reset --hard` 等) 除非用户明确要求。
- 必须将报错信息完整写入执行报告的"Issues & Errors"一栏。

## 3. 网络搜索与文档阅读能力

| 操作 | 用途 | 优先级 |
|------|------|--------|
| `web_search` | 搜索最新框架文档、API 参考 | **推荐** |
| `web_fetch` | 读取指定 URL 的文档内容 | **推荐** |

### 使用场景
- 遇到使用较新版本框架（如 Tauri 2.0、Vue 3.4）时，确认 API 未被废弃。
- 排查第三方库的已知 Bug 或兼容性问题。
- 查询 Python PEP / TypeScript 等语言规范。

### 注意事项
- 不得搜索或抓取与项目无关的内容。
- 优先使用官方文档源（如 `docs.python.org`, `fastapi.tiangolo.com`）。
- 不得将搜索到的代码直接复制粘贴，必须理解后适配项目。

## 4. 代码分析能力

| 能力 | 用途 | 优先级 |
|------|------|--------|
| 语法检查 (Lint) | 自动检测代码风格和潜在错误 | **必须** |
| 类型检查 (Type Check) | 静态类型分析 | **推荐** |
| 跨文件上下文理解 | 理解项目级依赖关系，不止单文件 | **必须** |
| 依赖分析 | 分析 import 关系，避免循环依赖 | **推荐** |
| 代码风格一致 | 模仿已有代码风格，保持项目一致性 | **必须** |

### 注意事项
- Agent 必须能够理解项目整体架构，而非孤立地看待单个文件。
- 修改代码前应先阅读同目录下的其他文件，理解项目约定（命名、目录结构、模块划分）。
- 不要在代码中添加冗余注释，如 `// 这是一个函数`。

## 5. Git 版本控制能力

| 操作 | 用途 | 优先级 |
|------|------|--------|
| `git status` | 查看工作区变更 | **必须** |
| `git diff` | 查看具体改动 | **必须** |
| `git log` | 查看提交历史 | **必须** |
| `git add` | 暂存变更 | **必须** |
| `git commit` | 提交变更 | **必须** |
| `git branch` | 分支管理 | **推荐** |
| `git push` / `git pull` | 远程同步 | **推荐** |

### Commit 规范
- 格式：`[#T{编号}] {type}: {简短描述}`
- Type: `feat` / `fix` / `refactor` / `test` / `docs` / `chore`
- 示例：`[#T001] feat: 搭建 FastAPI 项目骨架`

## 6. 测试能力

| 能力 | 用途 | 优先级 |
|------|------|--------|
| 编写单元测试 | 为功能代码编写测试用例 | **必须** |
| 运行测试套件 | 执行 `pytest` 验证功能正确性 | **必须** |
| 覆盖率检测 | 确保核心逻辑覆盖率 ≥ 80% | **推荐** |
| 测试报告解读 | 分析失败用例并修复 | **必须** |

## 7. 项目特定技能

### 当前技术栈
| 类别 | 技术 | 版本 |
|------|------|------|
| 语言 | Python | 3.11 |
| Web 框架 | FastAPI | latest |
| 服务器 | Uvicorn | latest |
| AI SDK | OpenAI | latest |
| 测试 | pytest | latest |
| Lint | Ruff | latest |
| 类型检查 | MyPy | latest |
| Git Hooks | pre-commit | latest |

### 编码约定
- Python 代码遵循 PEP 8 规范（由 Ruff 强制）。
- 使用 Type Hints（由 MyPy 强制）。
- 异步 API 使用 `async/await` 模式。
- 项目名称为 `writer`，源码目录命名待架构师确定（建议 `src/writer/` 或 `writer/`）。

## 8. 安全与伦理约束

- **不得**将 API Key、数据库密码等敏感信息写入代码或提交到仓库。
- **不得**执行未经授权的网络请求或数据上传。
- **不得**在未经批准的情况下引入外部依赖或修改项目架构。
- 所有文件操作限定在项目工作区内。
