# UAT — 用户验收测试协议

本 skill 覆盖 V2.0 起强制执行的 **四步交互式验收流程**。代码编写完毕、lint/type check 通过后必须调用，**不得跳过用户手工测试环节**。

## 四步流程

```
改代码 → 启服务 → 出指南(暂停等用户) → 合并反馈
```

### Step 1 — 完成代码编写/修改
- 修改或新增源代码文件
- 运行 `ruff check .` + `mypy .` 确保零报错

### Step 2 — 启动本地服务
- 执行 `python run.py` 或运行打包后的 `.exe`
- 确认控制台显示启动日志，浏览器已发起页面请求

### Step 3 — 输出《测试验收指南》并暂停 ⛔
- Agent **必须主动停止**，将测试验收指南输出给用户
- 指南内容覆盖:
  1. 控制台验证 — 检查启动日志无异常
  2. 浏览器界面验证 — 页面加载、UI 渲染
  3. 核心功能操作验证 — 具体操作步骤与预期结果
- **明确提示用户将测试结果反馈给 Agent**
- Agent 输出指南后等待用户回复，**不得擅自关闭服务或继续执行**

### Step 4 — 合并反馈生成最终报告
- 收到用户反馈后，将"执行详情"与"用户测试结果"合并
- 以标准 Execution Report 格式输出
- 若用户报告 Bug，在报告中标注并等待后续任务包修复

## 执行纪律

| 规则 | 说明 |
|------|------|
| **禁止跳过 UAT** | 完成代码后不得直接关闭服务并生成报告 |
| **禁止合并 Step** | 不得在输出指南的同时擅自关闭服务 |
| **主动暂停** | Agent 输出测试指南后，必须等待用户明确回复 |
| **如实记录** | 用户反馈须原样记录在执行报告中 |

## 执行报告追加章节

所有执行报告必须在"工作详情"之后新增:

```markdown
## 5. 用户测试反馈 (UAT Feedback)
<用户测试结论原文 / 问题描述 / 截图引用>
```
